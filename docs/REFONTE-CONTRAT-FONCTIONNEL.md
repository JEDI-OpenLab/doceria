# Contrat fonctionnel de la refonte UI (anti-régression)

> **Le filet de la refonte** (cf. `REFONTE-UI-ROADMAP.md` §1.1 et §4). Chaque fonction visible de
> l'app a UNE ligne : *emplacement actuel → cible → lot → statut*. Une ligne non « testée » (ou non
> actée « retirée volontairement ») **bloque la release**. Inventaire généré par passe multi-agents
> sur le code (2026-07-06, branche `refonte-ui`, 169 fonctions après déduplication), cibles
> affectées selon la répartition du plan. **À relire par l'utilisateur (lot 0)**, puis tenu à jour
> à chaque lot.
>
> **Statuts** : `à migrer` → `migré` → `testé` · `inchangé` / `inchangé-restylé` (re-testés en fin
> de lot quand même) · `retiré volontairement` (décision explicite).
